# Omnigraph v0.14.0 → v0.16.0: client SDK commit ledger

Every commit in `v0.14.0..v0.15.0` and `v0.15.0..v0.16.0` of ModernRelay/omnigraph, in order, with its effect on the Python SDK (`omnigraph-python`) and the TypeScript SDK (`omnigraph-ts`).
Impact is `none`, `python`, `ts` or `both`. Wire facts were checked against the `openapi.json` diff of each tag (see the summary), the release notes and the commits themselves, and the new behaviour was exercised live against servers built from v0.15.0 (release binaries) and v0.16.0 (source).

## Summary of wire changes

- The `Omnigraph-Http-Api` contract stays `0.14` in both releases. Both SDKs derived the header from the server minor; that is fixed first in each PR.
- 0.15 spec: `GET /branches?detailed=true` (`BranchDetailOutput`), `ReadOutput.ranking` (`RankingOutput`, `SearchFunction`, `RankOrder`), `AccessOutput.client_id`, `ErrorCode.not_admitted`, `SettingsRequest.change_lineage`, `LoadSliceExecutedOutput.read_ns`.
- 0.16 spec: `POST /graphs/{id}/operations/optimize`, `GET /graphs/{id}/operations/{op}`, `POST /graphs/{id}/operations/{op}/cancel` (`StartOptimizeRequest`, `OperationOutput`, `OperationLookup`), `ErrorCode.writer_fenced` + `ErrorOutput.writer_fenced` (`WriterFencedOutput`), `AccessAction.maintain`, 409/500 on the cluster deployment reads.
- Behaviour outside the spec: graphs without a policy refuse reads (0.16), request settings capped at server budgets (0.16), lost conditional race → `precondition_failure` (0.16), dry-run merge is a read (CLI, 0.16), converged direct apply releases its lock (0.16), U64 parameters above `i64::MAX` bind (0.15).
